Согласование полного контекста по порядку и времени исправляет этот класс ошибки; отдельные тесты сохраняют настоящий соседний повтор и новую фразу без перекрытия PCM.

## Публичные языковые примеры

`public-language-evaluation-final.json` оценивает один русский и один английский read-speech файл. WER — доля замен, удалений и вставок относительно числа эталонных слов после `gigaam.utils.normalize_raw_text()` и разделения на слова. Одинаковый регистр и оформление не используются как отдельные ошибки. Это небольшой контроль работоспособности, а не представительный benchmark.

| Вход | Длительность | Эталонных слов | Ошибок слов | WER | CPU-inference после загрузки модели |
| --- | ---: | ---: | ---: | ---: | ---: |
| Публичный RU | 11,290 сек | 26 | 0 | 0% | 2,894 сек |
| Публичный EN | 5,855 сек | 17 | 0 | 0% | 1,327 сек |

| Та же склейка через 8-секундный StreamProcessor | 17,495 сек | 43 | 1 | 2,33% | Отдельный замер latency не выполнен |

В прямом смешанном варианте модель заменила «надеждой» на «надеждый», в streaming-варианте — «лукоморья» на «лукомория». Этот результат сохраняет ошибки, а не объявляется точным. Streaming-запуск не выдал предупреждений; после остановки численный остаток очереди был `8.881784197001252e-16` секунды, то есть погрешность float около нуля, а не оставшийся аудиофрагмент. Python guard зарегистрировал 0 сетевых попыток.

Английский пример: sample `1272-128104-0000`, [LibriSpeech dummy / Hugging Face](https://huggingface.co/datasets/hf-internal-testing/librispeech_asr_dummy/tree/5be91486e11a2d616f4ec5db8d3fd248585ac07a), immutable revision `5be91486e11a2d616f4ec5db8d3fd248585ac07a`; PCM16 mono 16 kHz, SHA256 WAV `799f78ed4beb4de7ceae3a809262d4ce242394342ccd1d58cef7d49dbc2def46`. Источник — LibriSpeech/OpenSLR12, Vassil Panayotov и соавторы, CC BY 4.0; underlying книги LibriVox находятся в public domain. Запись lossless FLAC преобразована в PCM16 WAV без обрезки или ресэмплинга. Публикуются результаты, attribution и ссылка; файл речи остаётся локальным build-fixture.

Склейка двух разных дикторов и языков не воспроизводит естественную смешанную речь одного человека, разговор с шумом или одновременные голоса. Реальные KK/RU/EN-фразы, естественное переключение языков и запись через выбранные устройства остаются отдельными пользовательскими проверками.

## Автоматизированные тесты исходников

В окружении разработчика с установленными зависимостями:

```powershell
python -m pytest -q tests
```

Проверяются независимость одновременных источников и их частот, сохранение собственного clock, копирование переиспользуемого PCM-буфера, тихая речь, пауза/остановка и повторные timestamp-блоки. Окна проверяются на повторение одного акустического слова при смещённых метках на стыке и на сохранение самостоятельного «да да». Перегрузка должна быть ограниченной и видимой; ошибка inference не должна попасть в диагностическое сообщение с содержимым разговора.

Тест длительного потока продвигает часы двухчасовой записи ускоренно с fake-моделью. Он подтверждает ограничение очереди, одну параллельную inference-операцию и нулевой остаток после остановки. Он **не** является двухчасовой записью через оборудование, замером полного процесса с real GigaAM или доказательством стабильности многочасового GUI.

Fake WASAPI-тесты проверяют явный выбор устройств, отсутствие автоматической замены, отключение устройства, паузу и восстановление по команде пользователя. Тесты форматов используют сгенерированные строки, включая `ә ғ қ ң ө ұ ү һ і`, кириллицу, английский и повторы. Они проверяют кодировку, метки источников, порядок времени, сохранение прежнего файла, DOCX/XML и встроенный PDF-шрифт. Это проверка экспорта, а не распознавания этих языков.

Настоящий PCM integration-driver запускается отдельно в окружении разработчика с установленной CPU-моделью:

```powershell
python build/integration_pcm.py --report real-streaming-new.json
```

Драйвер устанавливает Python network guard до импорта сторонних библиотек, проверяет SHA256 публичного файла и модели, сравнивает прямой и потоковый выводы для обоих источников, общий timeline, ограничение очереди и автоматический idle-drain. Он не открывает аудиоустройства и не принимает пользовательский аудиофайл. Отчёт содержит только публичную фразу, технические данные и SHA256 проверенных исходников.

## Portable-проверка и сеть

Финальный rc2 EXE прошёл самопроверку с очищенными Python-переменными и минимальным Windows PATH: `frozen=true`, Python 3.12.3, точное распознавание русского control-file, экспорты и fake bounded-streaming. Время self-test — 36,461 секунды, счётчик Python network attempts — 0. Сетевой аудит сделал 51 выборку endpoints по PID, увидел 0 TCP/UDP, exit code 0. Встроенные Python bytecode/constants/exception tables/stack sizes/names совпали с проверенными текущими исходниками; пути отладки и line tables не использовались для сравнения.

Протоколы: `frozen-selftest.json`, `runtime-network-audit.json`, `frozen-source-match.json` из final-release-verification. Самопроверка исполняет упакованный runtime и читает модель с локального диска, без установки пользовательских Python/Docker-библиотек. PE import/delay-import аудит текущего каталога сборки уже прошёл: проверено 126 PE-файлов, отсутствующих зависимостей 0. Отдельный этап выпуска создаёт ZIP, SHA256 и manifest, затем проверяет CRC архива; эти результаты должны относиться именно к публикуемому ZIP.

Такая проверка уменьшает зависимость от окружения разработчика, но не подтверждает работу на чистой виртуальной машине без Python. Windows Sandbox на проверяемом компьютере отсутствовал. До отдельного прогона на чистой Windows VM это ограничение остаётся в протоколе. PE-аудит также не доказывает все возможные динамические `LoadLibrary`-пути.

Python socket/DNS guard устанавливается до импорта сторонних runtime-библиотек. Проводятся тест блокировки и проверка счётчика попыток; выборка TCP/UDP endpoints по PID EXE служит дополнительным наблюдением. Это не полная OS-level изоляция: она не видит каждое кратковременное или нативное обращение. При работе приложения Firewall, Defender и корпоративные ограничения не отключаются. Build-time скачивание зависимостей и модели выполняется отдельно.

## Пользовательская проверка оборудования и качества

1. Выберите микрофон и конкретный WASAPI loopback выхода, который действительно воспроизводит звонок. Если после начала звонка изменилось устройство вывода, обновите список и подтвердите нужный выход.
2. Подтвердите разрешение захвата и нажмите «Проверить уровни». Убедитесь, что движение шкал соответствует собственному голосу и отдельному воспроизведению системного звука. Это явная трёхсекундная запись для уровней.
3. Нажмите «Начать». Сначала проверяйте микрофон отдельно, затем системный звук отдельно. Для одновременного теста наденьте наушники, чтобы микрофон не слышал динамики.
4. Произнесите короткие казахские, русские, английские и смешанные фразы, включая два намеренных повтора одного слова. Сравните реальную речь с выводом, источниками и временем. Синтетические строки экспорта для этой оценки не подходят.
5. Проверьте «Пауза → Продолжить → Остановить». Дождитесь завершения очереди. Экспортируйте TXT, MD, DOCX и PDF под новыми именами, откройте каждый формат и проверьте казахские буквы.
6. Отдельно проверьте отключение выбранного устройства, переполнение очереди под нагрузкой и длительную запись. Ошибка должна быть видимой; новое устройство или запись не должны включаться автоматически.

При искажении текста сохраните точную публичную тестовую фразу, выбранный источник, шаги и технические сообщения.
